# 场景选择与叙事

同一数据契约服务五类任务。先确定读者要理解或完成什么，再选择素材与图，不要求每个任务展示全部源码。

## S1 教学章节

**素材**：章节提交范围、实际入口、教程材料。以章节新增概念组织地图，区分本节引入与此前复用。

**主线**：概念为什么需要 → 最小装配 → 核心调用 → 边界与练习。卡片解释关键抽象如何协作；在末站给一个可执行练习和预期现象。源码没有验证过的运行结果不写成事实。

**图**：全景展示模块职责，时序串起可运行入口，流程只展开本章最难的方法。

## S2 迭代对比

**素材**：用户给定的两个 Git 基线。先确认比较的是提交快照还是含工作区的状态。

```bash
node <skill>/scripts/extract-diff.mjs <repo> <base> <head>
```

**主线**：数据/接口变化 → 实现变化 → 使用方影响 → 验证与回滚。卡片回答变更动机、行为差异和影响面。没有资料支持的动机应标为推断。

**图**：只画变更模块与直接依赖，避免复制整个仓库架构。统计来自脚本或 Git，不估算成实测数字。末站记录回退基线与已知数据迁移限制；没有实际回滚验证时明确说明。

## S3 需求蓝图

**素材**：需求、验收标准、现有可复用代码。地图描述目标态，所有新增文件和方法明确标为计划。

**主线**：契约 → 骨架 → 核心逻辑 → 依赖接入 → 联调验收。树是计划的组件清单，卡片列关键接口、依赖与测试点，导览顺序尽量对应实现顺序。

**图**：目标架构、目标调用链和关键业务分支。不要把尚未确认的外部能力当成既定事实；在相关卡片写出待决策事项。末站放可核验的验收条件，命令中的未知配置保留清晰的占位说明。

## S4 PR 讲解

**素材**：PR 的 base/head 或分支；分叉分支通常从公共祖先比较。

```bash
node <skill>/scripts/extract-diff.mjs <repo> <base> <head> --merge-base
```

**主线**：要解决的问题 → 契约变化 → 关键实现 → 兼容性/异常路径 → 评审关注点。讲解应区分代码事实、作者意图和分析推断。

**图**：变更子图加一条核心时序即可。复用模块保留必要上下文，避免将未改动文件标为新增。卡片记录实际测试与未覆盖边界。只有任务包含代码评审时才给合并建议；普通 PR 讲解不自动扩展为评审结论。

## S5 架构入门

**素材**：仓库结构、启动入口、配置和一条真实业务请求。顶层包名不等于运行时关系，沿代码追踪关键调用。

**主线**：入口 → 应用/领域 → 持久化/外部系统 → 返回 → 异常边界。卡片说明模块职责、关键扩展点和阅读入口。

**图**：全景加最有代表性的时序；复杂分支再加流程图。不要尝试在一张地图中铺满大型仓库。若用户要全局理解，先画模块级概览，再围绕核心主题拆图。

## 共同约定

- 用 `new` / `modified` / `reused` / `external` / `warning` / `error` 表达状态，并在标题或副标题交代相对基线。入门图使用颜色区分职责时，在文案中说明语义。
- 一个说明卡至少关联一个树节点；有卡片的树节点至少有一个可解析的图锚点。导览提到的树节点必须在该站图中有锚点。
- 优先写真实标识符，解释文字放在卡片里。可读性不足时减少节点，不靠极小字体塞进全部信息。
- 主线独立阅读应能讲清主题；自由点击用于补充细节。
